# Workspace contract

The litigation stack remains layered.

`Litigation Analysis → Evidence Workspace → Legal Research → Pleading Workspace`

Each layer consumes identified inputs and emits traceable records. A later layer may not silently supply a missing earlier-layer fact. Use the existing matter ledger and Matter Memory mechanisms without duplicating records. Current original materials control over remembered summaries. Keep private matter files in the matter workspace. Private case materials must never enter public code repositories or public release packages. This isolation also covers internal ledgers, conclusions tables, litigation strategy, hearing/settlement plans, work records, synthetic-test inputs derived from private cases, attachments and metadata. A file being an internal record does not make it safe for public export. Use wholly synthetic fixtures for public tests. Any genuinely generic rule candidate must pass the existing de-identification and public-release controls before export.

## Required internal records

Establish and continuously maintain applicable internal records even when no user delivery file is requested. They may share one file or structured store. Cover procedural deadlines and backward work plan, fact timeline and evidence index, evidence gaps and adverse-use risks, request/accusation analysis, the single conclusions table under R2, material numbers and formulas, confirmed positions, structure-card and section approvals, versions and revision reasons, pending decisions and actual delivery status. Record oral or dialogue instructions with source, time and confirmation state. Preserve prior confirmed positions as history when superseded.

A changed conclusion must record the old and new position, reason and source, affected records/artifacts and synchronization status. Check the table, calculations, pleading, catalogue, materials, hearing and settlement positions as applicable. Reconfirm affected sections under R2. Record the current effective working version and distinguish draft, confirmed, delivery and submitted states using actual evidence.

Complex internal analysis may use conclusion → materials and scope → analysis → gaps and assumptions → decisions → next steps. Preserve full legal risk, possible outcomes, loss exposure and alternative strategies internally. External positions follow R4 and R11–R16 with truthful statements and mandatory disclosure duties.

## Hearing continuity and delivery

Reuse the existing hearing plan and case-research action matrix. Map applicable pleading sections to anticipated opponent and adjudicator questions, evidence locations, concise responses and lawful fallbacks based on available proof. Preserve counterattack, contradiction testing and alternative routes. Criminal questioning and rights analysis follow the actual role and stage.

Internal records are mandatory working records. User delivery files follow R8 and the explicit request. An unquoted catalogue item may still support a material issue or procedural duty. Review its purpose before removing it. Keep evidence numbering, name, page location and proof purpose consistent across requested artifacts. The pleading does not duplicate the catalogue as an independent evidence-source chapter.


## Capability levels and template limits

Analysis covers the roles and civil/criminal stages in R1 using current supplied materials and verified authority, with unresolved items kept pending. This describes an analysis workflow, not proof of successful handling of every possible procedure.

A text working draft may be developed after R2 analysis/table, structure and section controls (or the expressly scoped draft-first exception). A missing approved file template does not prevent a source-marked text working draft. Keep draft, confirmed text, formal file and submitted artifact states distinct.

Formal DOCX generation requires an actually selected, integrity-checked and approved matching template plus the existing quality/release checks. Bundled catalog entries labelled candidate are not approval evidence merely because the legacy resolver returns SELECTED. Verify private approval, current path and hash separately. If an approved private entry points to a missing old package, report that failure. Do not silently treat a bundled candidate or a civil template as an approved criminal/appeal/retrial/enforcement template.

The bundled catalog contains civil complaint/answer, commercial and labour/personnel arbitration application/answer, and evidence-catalog templates. Actual availability and private approval must be checked at execution. No bundled dedicated criminal defence, criminal complaint, victim-rights, appeal, retrial or enforcement templates are registered. Those formal-file capabilities remain pending a matching approved template and successful resolution. Procedural applications, preservation, objections, private prosecutions, incidental civil claims and other special variants also require exact variant checks. An existing generic type does not establish universal procedural coverage.
