# Redline and File Quality Gate

## 脚本硬门

`scripts/redline_quality_gate.py` 必须返回 `PASS` 且退出码 `0`。它验证：

1. 原合同、修订版均为完整无宏 DOCX ZIP；修订版启用 `w:trackRevisions`。
2. 主文、页眉、页脚、脚注和尾注全部纳入比较，表格行列结构不得漂移。
3. 拒绝指定作者修订后的视图与源合同逐段一致；接受后的视图可正常读取。
4. 插入、删除的作者和非空修订结构可识别，数量与长度统计可诊断。
5. 批注仅用于必须由用户确认事实或作出商业决策的事项，且限定为影响合同签署、付款、验收、责任承担等核心事项的少量关键待确认项，其他事项列入内部审核报告、不添加批注；一般修改/新增段落不加批注。每条只处理一个待确认事项，锚定最小必要正文范围，仅一句明确短句提问。批注文本原则上不超过 30 个中文字符（超过 30 字告警提示优化）；超过 50 字、无正文锚点、范围批注 start/end ID 不平衡、命中明确多事项模式（两个及以上问号；两个及以上"是否"或重复"请确认/需确认"；"分别确认/另请确认/同时请确认/还需确认"；"1/2、A/B、第一/第二"枚举——仅标点或普通并列词只作 WARNING 依据，不得据此 FAIL），或对一般修改/新增段落添加批注，均直接 FAIL。
6. 由主审或指定复核人复核接受修订后的主体、金额、日期、编号、附件引用和关键法律文字；DOCX 通过结构与可访问性检查后，再执行交付前秒级基础校验（见下节）。

## 交付前秒级基础校验

交付前执行以下秒级源文件校验，完成后直接交付修订版 Word：

1. **原文件未被覆盖**：原件只读，派生文件另存；原件 SHA-256 与 matter manifest 一致。
2. **文件可正常打开**：修订版为完整无宏 DOCX ZIP，ZIP 结构与 OOXML part 可解析。
3. **修订痕迹存在**：`w:trackRevisions` 启用，`w:ins`/`w:del` 存在，作者符合隔离规则。源文件已有其他作者修订时，本轮不得未经授权接受、拒绝、改作者或移除这些历史修订节点；本轮作者修订被拒绝后，历史修订状态仍应与源文件一致。
4. **修改范围符合指令**：修改范围与当次指示、内部审核报告一致，无非预期增删。
5. **接受/拒绝修订后的文字逻辑正确**：拒绝修订后的视图与源合同一致；接受修订后的视图可读取，且关键法律文字经主审或指定复核人复核。

**版式保真原则**：
- 原文件为 `.docx`：直接在原 OOXML 文件上进行最小化修订，保持原有字体、样式、表格、页眉页脚及页面设置。
- 原文件为 `.doc`：仅允许先转换为 `.docx`，并先通过 T-09 的源文件—转换文件保真检查后再修订。

## 修订颗粒度

能改一字不改一句，能改一句不改一段；原文缺失必要机制时可以新增完整句段。复核强度取决于修改的法律影响，不取决于字符长度，不生成按长度触发的变更台账。

## 必然失败

- 可局部修改却整句删除再插入，导致不必要地扩大修订范围；
- 存在未记录的非修订文字变化；
- 源合同与拒绝修订后的视图不一致，或接受修订后的视图无法读取；
- 批注孤立、范围锚点不平衡；
- 批注超 50 字、单条命中明确多事项模式，或对一般修改/新增段落添加批注；
- 生成器、报告或人工说明声称 PASS，但脚本实际未执行或退出码非 0。

真正缺失的条款可以是长句或整段；主审或指定复核人按法律影响复核其必要性和表达。
